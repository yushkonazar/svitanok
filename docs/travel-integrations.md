# Подорожі: житло, автобуси та інтерактивна мапа

Підготовлено 23.10.2026. Основне планування залишається у Mini App, у порядку транспорт → житло → місця. Вибір рекомендації не створює бронювання.

## Що реалізовано

- Короткі картки пропозицій із ціною та її обсягом, фактами, рейтингом із назвою джерела, розкривними умовами й переходом до сервісу. Підтверджена повна сума відрізняється від ціни за людину/ніч. Невідомі ціни не займають головний заголовок картки.
- Booking/Airbnb: переходи з датами саме проживання, кількістю гостей і кімнат. Для конкретного об’єкта з Booking/Airbnb зберігається його пряма сторінка; для об’єкта з іншого сайту можна шукати його назву на Booking. Це не твердження, що цей об’єкт обов’язково є на Booking.
- INFOBUS/FlixBus: пошук дослідником із пріоритетом цих джерел та прямі переходи. Для Львів → Прага використано перевірені сторінки напрямку. Дати й пасажирів для автобусів користувач перевіряє на сайті: непідтверджені параметри публічної пошукової форми не вигадуються.
- Дослідник шукає 6–8 різних доречних варіантів, контракт допускає 12; кількість не доповнюється вигаданими результатами. Є «Показати ще» й окремий пошук наступних кандидатів зі списком уже знайденого.
- OpenAI trip-research отримує сувору JSON-схему коротких карток і обов’язковий вебпошук першого виклику. Інші профілі зберігають свої формати. Заміни моделі немає.
- Реальний адаптер Booking Demand v3.2 search/look/redirect: датовані ціни на групу, деталі об’єкта, фотографії, оцінки, пагінація. Без ключів цей шлях не викликається. Sandbox не підмінює реальні пропозиції в плануванні.
- Мапа у результатах пошуку: місто, зіставлені точки житла/місць і відкриття відповідної картки натисканням позначки. Перегляд позначки не додає місце у план. Дорога має окрему мапу з орієнтовним автомобільним маршрутом.

## Підключення Booking

Особисте використання не скасовує вимоги [Managed Affiliate Partner та договору](https://developers.booking.com/demand/docs/getting-started/prerequisites). Наразі такого доступу немає. Звичайний обліковий запис мандрівника не є API-ключем.

Потрібні серверні налаштування:

| Назва                    | Призначення                                                                        |
| ------------------------ | ---------------------------------------------------------------------------------- |
| `BOOKING_API_TOKEN`      | Партнерський API key token, зберігати як Cloudflare secret                         |
| `BOOKING_AFFILIATE_ID`   | Partner affiliate ID, зберігати як Cloudflare secret                               |
| `BOOKING_BOOKER_COUNTRY` | Фактична країна booker дволітерним кодом, не автоматичний висновок із громадянства |
| `BOOKING_API_ENV`        | `production` лише після доступу до бойового середовища; інакше sandbox             |

Адаптер використовує тільки accommodations/constants, accommodations/search і accommodations/details, без створення замовлень та платежів. Вік дітей потрібний для точного API-запиту; без нього працює вебпошук із коротким поясненням. Статичний опис номера не вважається доступністю на дати. Фотографії приймаються лише від авторизованого адаптера, з перевіркою домену Booking CDN; вебдослідник не може підкласти власні фото або координати під виглядом відповіді постачальника.

Навіть партнерський API може мати [інший склад пропозицій і ціни, ніж сайт Booking](https://developers.booking.com/demand/docs/accommodations/search-for-available-properties). Genius та персональні тарифи не обіцяються. Остаточні деталі користувач бачить на Booking у власному сеансі входу. Знижки та [підключення акаунта через Data Portability](https://developers.booking.com/datasecurity/registration) потребують окремого погодженого доступу; у цій реалізації паролі й cookies Booking не збираються.

## Airbnb та інші джерела

Повторна перевірка [офіційної програми Airbnb API](https://www.airbnb.com/help/article/3418) не підтвердила відкритого персонального guest-search API. Реалізовані переходи до житла/пошуку; це не підключення Airbnb-акаунта.

Найбільш придатні альтернативи для подальшого випробування:

- [Nuitee Connect / LiteAPI](https://docs.liteapi.travel/docs/faq): API тарифів, контенту й фото з самостійною реєстрацією. Перед увімкненням потрібно підтвердити search-only сценарій, коли бронювання відбувається на іншому сервісі: безкоштовні виклики залежать від [умов look-to-book](https://docs.liteapi.travel/reference/api-pricing-usage-costs).
- [Amadeus Self-Service](https://admin.developers.amadeus.com/self-service/apis-docs/guides/developer-guides/faq/): доступні розробнику готельні API, але без фото готелів у Self-Service. Не замінює власний Booking-акаунт.
- [INFOBUS / BusSystem](https://bussystem.eu/uk/agents) та [FlixBus dynamic integration](https://www.flixbus.com/company/partners/affiliate-partners): прямі автобусні API потребують партнерського доступу. Для них не вигадано неофіційних endpoints або підроблених API-статусів; зараз працюють вебпошук і переходи.

## Налаштування Google Maps

| Назва                  | Призначення                                                                    |
| ---------------------- | ------------------------------------------------------------------------------ |
| `MAPS_API_KEY`         | Наявний серверний ключ Places/Routes/Geocoding, залишається тільки на сервері  |
| `MAPS_BROWSER_API_KEY` | Окремий браузерний ключ; лише Maps JavaScript API та дозволені HTTP referrers  |
| `MAPS_MAP_ID`          | Власний JavaScript Map ID; тестовий DEMO_MAP_ID у production не підставляється |

Для production дозволений referrer `https://svitanok.yushko.dev/*`. Тимчасовий локальний перегляд `http://127.0.0.1:53749/*` можна додати для перевірки й прибрати після неї. Наявні серверні ключі не розширюються й не публікуються.

Maps JavaScript API уже ввімкнений у Google Cloud-проєкті `svitanok-apis`. Налаштування браузерного ключа й Map ID — окремий крок перед ввімкненням мапи. Без них користувач бачить зрозумілий перехід до зовнішнього Google Maps.

Відображення справжньої мапи поки не підтверджене: створення окремого ключа очікує погодження власника. Локальна перевірка з явно недійсним тестовим ключем підтвердила запуск Google JS та зовнішній fallback, але також показала внутрішній Google `SecurityError` у sandbox. До ввімкнення потрібно перевірити справжній обмежений ключ, роботу позначок і сумісність sandbox; за потреби винести переглядач на окремий origin. Цей тест не є підтвердженням працездатності живої мапи.

Map data отримується лише після owner-auth на `/api/trips?format=map&id=…&kind=stay|transport|activity`. Пошук координат запускається після відкриття мапи, для максимум восьми актуальних кандидатів. Неоднозначне чи віддалене співпадіння не стає позначкою. У списку видно об’єкти, які не вдалося позначити. Повторне відкриття в межах десяти хвилин використовує кеш поточного інтерфейсу.

Google Maps JavaScript працює в `sandbox` iframe без `allow-same-origin`, із власним документом і політикою CSP. Основний застосунок зберігає заборону `unsafe-eval` та звернення API лише до свого origin. Налаштування CSP мапи враховує [офіційні вимоги Google](https://developers.google.com/maps/documentation/javascript/content-security-policy). Повідомлення позначок перевіряються за конкретним iframe, opaque origin і списком дозволених ID. Ключ передається повідомленням у цей iframe, а не в URL сторінки.

Автомобільна тривалість Google має відповідний підпис. Вона не замінює розклад автобуса, не доводить його трасу й не містить окремого прогнозу черги на кордоні. Час кордону не додається до розкладу повторно автоматично.

## Перевірка і запуск

- Перевірити коректність параметрів для випадку «двоє в автобусі, четверо у житлі, заселення наступного дня».
- Перевірити дії карток, розкриття умов, продовження пошуку й незмінність owner-вибору після натискання мапи.
- Перевірити відсутність витоку серверного ключа та неприйняття повідомлень від сторонніх вікон.
- У браузері перевірити справжню мапу з обмеженим ключем, позначки й зв’язок із картками, адаптивність та відсутність помилок CSP.
- Зміни Worker, Mini App, Brain і інструкції дослідника мають публікуватися узгоджено. Для змін інструкції використати штатну синхронізацію інструкцій.

Партнерські сервіси не реєструвалися, договори не приймалися й бронювання не виконувалися. Отримання комерційного доступу до Booking/INFOBUS/FlixBus залишається зовнішньою залежністю.

Локально пройшли 6224 основні тести з перевіркою покриття, 529 тестів інтерфейсу й 7 перевірок у workerd. Окремо перевірено незмінність JSON з вебцитатами, локалізовані назви/адреси Booking, відмову від перенаправлень API та адаптивність карток на ширині 320 і 430 px. API-відповіді в цих тестах синтетичні: справжні тарифи Booking без партнерського доступу не перевірялися.
