# Mini App: локальна перевірка та майбутній реліз

Стан на 4 жовтня 2026. Worktree `.workspace/mini-app-renewal`, гілка `feat/mini-app-renewal`. Цей документ описує порядок перевірки. На початку роботи власник заборонив push/deployment через автоматичний production deployment Cloudflare навіть після push робочої гілки. Пізніше дозволив окреме статичне мобільне демо; воно опубліковане без Worker та приватних даних. Після UX-правок власник хоче перейти безпосередньо до релізу, без ще одного демо-посилання. Production на цьому етапі ще не змінено.

## Що вже можна перевірити локально

Відкрити `http://127.0.0.1:5174/app/`. Поза Telegram це позначене демо: справжні фінанси й приватні API не використовуються. Зміни демо фінансів і підтвердження чек-іну зберігаються у браузері; відповідні кнопки скидання повертають приклади. Справжній авторизований збій API не перемикає користувача на демо.

- Сьогодні: циферблат, розділені години опадів, конвертер за кнопкою з `1 234,56`, вибір валюти, графік спостережень за кнопкою, факт/цитата з джерелом, історична мапа без артефактів перетину 180-го меридіана та швидкі дії.
- Фінанси: записати витрату й дохід; уточнити ручну операцію; перевірити зміну балансу й бюджету; зарезервувати/повернути кошти цілі; створити платіж, кредит і бюджет; приховати/повернути таксі та змінити режим доходу.
- Таксі: чиста каса 4 000, комісія 700, пальне 1 000 → 1 500 при 50/50 та 1 735 при 55/45. Поріг строго понад 27 000 брудної каси за тиждень, підвищена частка для всього тижня. Паливна картка не змінює особистий баланс. Неповні дані явно позначаються, розрахунок не підтверджується до їх уточнення.
- Чек-ін: назад/далі, точний вибір стану, чернетка, явне підтвердження, наступний слот/таймер, reload. «Мій стан»: періоди, порівняння, покриття й пропуски.
- Новини: українські заголовки, пошук, CS2/футбол, джерело й стаття, відкриття оригінального заголовка. Демо — статичні приклади RSS 4 жовтня, не поточна стрічка.

Локальні автоматичні перевірки: кореневі `npm test` та `npm run typecheck`; у `web/app` — `npm test`, `npm run lint`, `npm run build`; lint зміненого серверного коду, `git diff --check`. Фінансові сценарії виконуються на тимчасовій SQLite-базі з реальною міграцією `0028`, без доступу до Cloudflare.

## Порядок після окремого дозволу на реліз

1. Повторно звірити гілку, погоджений diff, цільове середовище й механізм deployment. Через наявну Cloudflare-інтеграцію не використовувати push як спосіб попереднього перегляду.
2. **Спочатку резервна копія** D1 та чинного застосунку. Перевірити можливість відновлення, зберегти ідентифікатор копії поза репозиторієм. Нові 11 таблиць включені в backup/export/forget/restore; старі backup-файли можуть не містити їх і повинні відновлювати нейтральні початкові значення.
3. Звірити список застосованих міграцій із `web/core/migrations`. Застосувати тільки відсутню expand-міграцію `0028_mini_app_finance.sql` у явно обраному середовищі. Вона не повинна замінювати старі фінансові записи чи заповнювати справжні рахунки демонстраційними сумами. Перевірити таблиці, індекси, унікальність команд/розрахунків і початкові нульові ручні баланси.
4. Зібрати frontend і Worker з цього ж погодженого стану коду, повторити тести. Опублікувати лише способом, погодженим власником. За можливості спочатку використати ізольоване середовище з тестовими bindings; production bindings не підставляти в локальне демо.
5. Перевірити Telegram auth: відсутній/прострочений initData → 401, сторонній користувач без права запису → 403. Owner має доступ. Невалідна сума → 400, застаріла версія → 409, повтор тієї ж команди не дублює операцію. Недоступний D1 показує помилку, а не фінансові приклади.
6. Звірити наявний Monobank webhook, reconciliation і ліміти запитів. Не перестворювати webhook без потреби. Повтор доставки однієї операції дає один запис. Hold не дозволяє підтвердити платіж. Непідтверджений баланс залишається невідомим. Прив’язка імпортованого платежу/розрахунку з парком не створює друге списання; фактичну банківську операцію не виконувати заради тесту.
7. Перевірити cron у поточному режимі асистента: новини раз на 3 години, чинний брифінг, налаштування нагадувань, тихі години/focus, постановка та дренування outbox. Увімкнення нагадувань у реальному середовищі звірити з власником. Повтор/помилка доставки не створює нове нагадування за той самий період. Нагадування не списує гроші й не позначає платіж сплаченим.
8. Перевірити на iPhone 15 Pro у Telegram: клавіатура сум, safe area, висота Mini App, прокрутка/модальні форми, links, reduced motion та haptics. Підтверджений чек-ін після повторного відкриття залишається підтвердженим; застарілий слот не перезаписує сьогоднішні відповіді.
9. Зі справжніми початковими залишками звірити один завершений тиждень таксі вручну. Перезмінка — понеділок 13:00 Europe/Kyiv, включно зі зміною часу. Готівка від клієнтів не дорівнює чистому доходу: резерв повернення парку зберігається після особистих витрат і початку нового тижня. Підтверджений розрахунок не створює повторного доходу.

## Контент і витрати

RSS: чотири стандартні видання — Українська правда, BBC, HLTV та Sky Sports. BBC має три стрічки (світ, технології, наука); разом за замовчуванням шість RSS. Guardian — додаткове джерело, вимкнене за замовчуванням. До трьох матеріалів зі стрічки, загальний максимум 18 у добірці й пакетній локалізації раз на 3 години. Повторні URL усуваються між стрічками. Україномовний заголовок і короткий витяг не перекладаються через LLM. Незмінені URL/заголовок/витяг використовують SHA-256 кеш; за збою LLM залишається оригінал. Використовується вже наявний LLM-хост, без нового API-ключа. Витяг не видається за повний текст статті. Наявність робочого хоста й фактичну вартість перевірити в цільовому середовищі; локальні тести використовують mock і не підтверджують якість майбутніх відповідей моделі.

30 фактів із редакційною перевіркою первинних джерел та 30 власних українських переказів стоїків обертаються детерміновано. Це стартовий циклічний каталог, а не автоматична обіцянка 30 нових перевірених фактів щомісяця. Поповнення вимагає перевірки джерел; старі неперевірені LLM-факти не публікуються. Історія валют накопичується від першого датованого спостереження, без вигаданих минулих значень.

## Якщо реліз потрібно відкотити

Відкотити код/статичні assets до збереженої версії погодженим способом. Expand-таблиці зберегти: не робити drop і не стирати нові фінансові записи. Відновлення бази із копії — окреме рішення, оскільки може прибрати операції, записані після копіювання. Перед поверненням нової версії звірити командні версії, банківські ID, підтверджені розрахунки й outbox, щоб не повторити записи/повідомлення.

## Підготовлений релізний кандидат

Гілка перейменована на `feat/mini-app-renewal`. База звірена через `git fetch origin main`: `d4b68b8250a02d573b26ba1324f68c03e1f23513`. Локальний `main` в основному checkout старіший; його не використовувати як базу релізу. Незастосовані remote-міграції перевірено read-only 4 жовтня: **тільки `0028_mini_app_finance.sql`**. Перед фактичним релізом повторити цю перевірку.

Cloudflare CLI авторизований. Read-only перевірка deployment зафіксувала Worker version `966d1f3f-9bfd-445a-a516-98dcaa6b16b2`, 100% трафіку; deployment `a259f20b-5434-440c-a3e3-f00c5c52dd6d` від 3 жовтня. Це попередній checkpoint, який треба звірити ще раз перед публікацією.

### Порядок запуску

Команди нижче — підготовлений порядок, а не підтвердження виконаного deployment. Запускати з чистого checkout релізного коміту та перевіряти код завершення після кожного кроку. Використати Node 24, як у `.nvmrc`, і Wrangler із lockfile.

1. Звірити `git status`, SHA кандидата з локальним release manifest, актуальний `origin/main` та поточну Worker version. Не робити push робочої гілки як спосіб перевірки: він може запустити production build. Підготувати контрольований запуск і зупинити конкурентну публікацію під час релізу, якщо вона є.
2. Безпосередньо перед міграцією зберегти резервну копію D1 у приватному каталозі **поза Git та опублікованим демо**. Перевірити ненульовий розмір та SHA-256 копії; зберегти актуальну Worker version й ідентифікатор чинного зашифрованого backup Світанку. Не виводити записи бази в журнали.

   ```powershell
   # Підставити приватний абсолютний шлях. Це створює локальний SQL-експорт.
   node node_modules/wrangler/bin/wrangler.js d1 export svitanok --remote --config web/wrangler.jsonc --output $releaseBackupPath
   ```

3. Перевірити список pending migrations. Якщо він відрізняється від очікуваного, спочатку розібрати різницю. Для поточного кандидата застосувати 0028 **до будь-якого push/deploy**, а не чекати паралельний GitHub workflow після merge.

   ```powershell
   node node_modules/wrangler/bin/wrangler.js d1 migrations list svitanok --remote --config web/wrangler.jsonc
   node node_modules/wrangler/bin/wrangler.js d1 migrations apply svitanok --remote --config web/wrangler.jsonc
   ```

4. Звірити `d1_migrations`, нові 11 таблиць і початкові нульові ручні залишки. Далі опублікувати **саме перевірений коміт** узгодженим способом. Наявний GitHub `migrate.yml` побачить уже застосовану міграцію; нові таблиці не конкуруватимуть зі стартом Worker. У Cloudflare build command має бути збірка `web/app` перед `wrangler deploy`, щоб `/app/` не залишився на попередньому frontend. Не поєднувати ручний deploy з неконтрольованим автоматичним build.
5. Перевірити зелені CI, D1 migrate та Sync instructions; підтвердити завершений Cloudflare build й активну version. Brain-код не змінено і workflow `deploy-host` за його paths не має запускатися від цього кандидата. Його типи, залежності та збірка перевіряються для сумісності; VPS не переустановлювати без потреби.
6. Увійти як власник через Telegram, виконати читання й одну погоджену ручну фінансову операцію. Перевірити збереження після повторного відкриття, відсутність демо при помилці API, підхоплення наявного банківського імпорту, правильний залишок/резерв і зміну бюджету. Не ініціювати справжній банківський платіж заради перевірки. Перевірити новини після першого cron-циклу, чек-ін та налаштування нагадувань.

### Відкат коду

Якщо попередня version усе ще є правильним checkpoint, підготовлена команда:

```powershell
node node_modules/wrangler/bin/wrangler.js rollback 966d1f3f-9bfd-445a-a516-98dcaa6b16b2 --config web/wrangler.jsonc --message "Mini App release rollback"
```

Таблиці 0028 та внесені після релізу дані зберегти. Окремо повернути Git-джерело до погодженого попереднього стану, щоб наступний автоматичний build не відновив проблемний код. SQL-restore не запускати автоматично як частину відкату Worker.
