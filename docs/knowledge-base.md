# Вузька персональна база знань

Статус: foundation. Цей модуль **не** читає весь Drive і не підключає hosted
file search. Він існує, щоб асистент міг відповідати лише з явно дозволеного
корпусу та показувати походження відповіді.

## Межа доступу

Дозволені типи: `cv`, `job_preparation`, `learning`. Кожен документ додається
окремо з власним `source_type` та `source_ref`; наявність Google Drive scope не
є дозволом на індексацію. У першому релізі `access_scope` завжди `owner`.

Заборонено: whole-Drive ingestion, пошта, приватні чати, автоматичне додавання
файлів за назвою або передавання документів у сторонній hosted file search.

## Дані й версії

`knowledge_documents` зберігає allowlist та статус. Кожна зміна створює
`knowledge_document_versions` з хешем вмісту; `knowledge_chunks` належать рівно
одній версії та несуть номер фрагмента, необов'язкові section/page і стан
проєкції. D1 — truth. Векторний індекс, коли буде увімкнений, є лише
rebuildable projection за стабільними `vector_id`.

Відповідь асистента з бази знань мусить містити назву документа, версію та
section/page кожного використаного фрагмента. Якщо evidence немає — відповідь
має прямо це сказати, а не домислювати.

## Відкликання та видалення

`revoked` негайно прибирає документ і всі його версії з retrieval. Видалення
спершу видаляє вектори, потім D1-чанки, версії та документ; результат входить
у квитанцію `forget`. Це не впливає на пам'ять розмов (`memory_chunks`) — дві
системи зберігання навмисно розділені.
