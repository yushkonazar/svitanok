# Вузька персональна база знань

Статус: foundation. Цей модуль **не** читає весь Drive і не підключає hosted
file search. Він існує, щоб асистент міг відповідати лише з явно дозволеного
корпусу та показувати походження відповіді.

## Межа доступу

Дозволені типи: `cv`, `job_preparation`, `learning`. Кожен документ додається
окремо з власним `source_type` та `source_ref`; наявність Google Drive scope не
є дозволом на індексацію. У першому релізі `access_scope` завжди `owner`.

Заборонено: whole-Drive ingestion, пошта, приватні чати, автоматичне додавання
файлів за назвою або передавання документів у сторонній hosted file search.

## Дані й версії

`knowledge_documents` зберігає allowlist та статус. Кожна зміна створює
`knowledge_document_versions` з хешем вмісту; `knowledge_chunks` належать рівно
одній версії та несуть номер фрагмента, необов'язкові section/page і стан
проєкції. D1 — truth. Vectorize є rebuildable projection за стабільними
`vector_id`: `pending/failed → upsert → ready`; стара версія ховається лише
після успішного upsert нової.

Відповідь асистента з бази знань мусить містити назву документа, версію та
section/page кожного використаного фрагмента. Якщо evidence немає — відповідь
має прямо це сказати, а не домислювати.

Поточний lifecycle уже має вузькі операції `ingestKnowledgeDocument`,
`searchKnowledge`, `runKnowledgeList`, `revokeKnowledgeDocument` і
`deleteKnowledgeDocument`. Ingest приймає тільки текст,
який передав окремий authorizing adapter, та є ідемпотентним за
`(source_ref, source_version)`. Пошук бачить тільки `ready`-фрагменти;
планувальник безпечно повторює індексування pending/failed версій з D1, не
читаючи файл повторно.

## Відкликання та видалення

`knowledge.list` показує власнику лише безпечні метадані (id, назву, тип,
статус і дати) — без тексту, `source_ref`, Drive URL чи vector id. `revoked`
негайно прибирає документ і всі його версії з retrieval та вимагає T1
підтвердження ✅. Реалізоване фізичне видалення спершу видаляє вектори, потім
D1-чанки, версії та документ; якщо вектори є, але Vectorize недоступний, D1
не змінюється. Воно проходить T2 (✅ + слово). Це не впливає на пам'ять розмов
(`memory_chunks`) — дві системи зберігання навмисно розділені.
