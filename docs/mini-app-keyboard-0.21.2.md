# Mini App 0.21.2: введення над мобільною клавіатурою

## Проблема

Під час введення міста у формі «Куди вирушимо?» нижня навігація перекривала поле, а клавіатура закривала кнопку. Оболонка тримала фіксовану панель і відступ для звичайного екрана, не реагуючи на зміну видимої області.

## Поведінка

- Спільна оболонка приховує навігацію на початку мобільного введення. Використовує `VisualViewport`, зміну висоти вікна та `Telegram.WebApp.viewportChanged`.
- Відступ унизу враховує лише перекриту частину layout viewport. На Android зі зменшенням самого layout viewport додатковий відступ на висоту клавіатури не додається.
- Після зміни розмірів поточне поле прокручується у видиму область. Короткі форми міста та власної відповіді в подорожах позначені групою: коли вся група вміщується, видно також кнопку. Для завеликої групи пріоритет має поле.
- Навігація повертається після відновлення виміряної висоти, навіть якщо iOS залишає фокус у полі. Коли клієнт не повідомляє геометрію клавіатури, запасний режим діє до втрати фокуса.
- Заміна сфокусованої форми після збереження також повертає навігацію, навіть без події втрати фокуса чи зміни viewport.
- Ручне прокручування не повертає користувача до поля. Pinch zoom, звичайне desktop-введення, checkbox і read-only не вважаються мобільною клавіатурою. Поворот пристрою оновлює базову висоту.
- Вкладена панель прокручує свій контейнер, без прокручування заблокованого документа позаду неї.

Форма залишається змонтованою. Зміна viewport не надсилає запит збереження, не змінює маршрут і не переписує дані. Серверні дані, API-контракти й схема бази не змінюються.

## Перевірка

Регресійні тести моделюють iOS із перекритим layout viewport, Android зі зменшенням обох viewport, Telegram без `VisualViewport`, закриття клавіатури зі збереженим фокусом, поворот, zoom і вкладений скролер. Інтеграційний тест рендерить справжню оболонку та форму подорожі: введене місто переживає зміну viewport і надсилається один раз після явного натискання кнопки.

Локально пройшли 6170 основних тестів у 295 файлах і 514 тестів у 72 файлах Mini App, збірка, перевірки типів, обидва лінтери та перевірка форматування.

Команди:

```sh
npm --prefix web/app test -- --maxWorkers=2
npm --prefix web/app run lint
npm --prefix web/app run build
npm run typecheck
npm run lint
npm run format:check
```

У поточній сесії інструмент Computer Use не надав жодного браузера. Тести геометрії працюють у jsdom; візуальну перевірку у справжньому iOS Telegram не виконано. Після розгортання слід перевірити введення міста та власної відповіді, ручне прокручування і повернення навігації після закриття клавіатури. Наявність release notes сама по собі не підтверджує production deployment.

Джерела поведінки API: [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport), [Telegram viewport і події](https://core.telegram.org/bots/webapps#initializing-mini-apps), [втрата фокуса після видалення елемента](https://developer.mozilla.org/en-US/docs/Web/API/Element/blur_event).
