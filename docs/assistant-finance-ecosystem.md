# Фінансові сповіщення: асистент + Mini App

Підготовлено 11.10.2026 від `main a583398` (Mini App 0.3.9).
Цей документ описує зміни робочої гілки, не підтверджує production deployment.

## Поведінка

- Покупки й аналітичні ознаки залишаються в обліку. Новий продавець,
  велика сума, валюта або припущення про підписку самі собою не створюють
  повідомлення в Telegram. Пошук незвичних операцій за запитом збережено.
- Можливі подвійні списання не називаються доведеним дублем чи шахрайством.
  Кнопки: відкрити операцію, позначити для своєї перевірки або підтвердити
  різні покупки. Відповідь зберігається, картка редагується на місці.
- Позначення не змінює суму, баланс, категорію чи графік платежу,
  не скасовує банківську операцію і не підтверджує оплату договору.
  Mini App показує нерозглянуті списання й ту саму відповідь власника.
- Єдине джерело планових оплат - `finance_payments`. За ввімкненого
  налаштування повідомлення з'являється о 11:00 за Києвом, не раніше дня
  після планової дати. Якщо доставка була приглушена, наступний дозволений
  запуск підхоплює непідтверджений платіж. Повторів на ту саму дату немає.
- Непідтверджені оплати зводяться в картку, до десяти записів за один
  запуск. Кожна кнопка веде до конкретного ID. Назви 12M/24M і різні
  договори LoveYouHome зберігаються; об'єднання за назвою чи сумою немає.
- Виявлені банком інтервали з `subscriptions` залишаються прогнозами для
  аналізу. Старі розсилки `subscription-remind` та підказки про майбутнє
  списання вимкнено. Облік і старі API підписок не видаляються.
- Підтвердження оплати виконується через чинну команду `payment-paid`;
  для імпортованого списання використовується зв'язок з операцією без
  другого списання в обліку. Нові кнопки повідомлень цього не підміняють.

## Надійність і доступ

- Обидва інтерфейси використовують чинний фінансовий command path:
  перевірку версії, журнал команд і атомарну зміну даних.
- Версія перевіряється в кожній зміні всередині batch, не лише перед нею.
  Виправлено відтворену гонку: повтор того самого ID й часу не може
  затерти новіше рішення, навіть якщо рання перевірка вже пройшла.
- Відповідь на фінансове попередження зберігається в `raw_json.financeAttention`
  як status/at/source. У моделі й клієнті - лише ці дозволені поля.
  Нової схеми D1 або перенесення записів цей блок не потребує.
- При помилці збереження кнопки не зникають. Якщо збереження пройшло,
  але Telegram не оновив картку, тост чесно розділяє ці результати.
  Повторний tap відновлює картку без повторної мутації.
- Сповіщення про оплату і її індивідуальна позначка доставки додаються
  однією D1 batch-транзакцією. Перед постановкою в чергу статус і дата
  платежу перевіряються знову. Відкриття посилання читає поточний стан.
- Старі кнопки сумісні: «Ок» не підтверджує оплату; під старим питанням
  про дубль «Ні» означає різні покупки, «Так, перевірю» - власну перевірку.
  Старі модельні follow-up запити не прибирають кнопки до прийняття чергою;
  збій дозволяє повторити запит.
- Посилання лише вибирає екран. Доступ захищається чинною перевіркою
  власника та підписаних Telegram initData, не ID чи startapp-параметром.
  У групі без налаштованого username немає оманливої кнопки, що відкриє демо.
- Грошові розрахунки й ці кнопки не вимагають нових модельних викликів.
  Аналітика, пам'ять, нові розсилки й доступи не вмикаються цим релізом.

## Перевірка після релізу

1. Звичайна покупка від нового продавця: запис є у фінансах, повідомлення
   лише через назву або суму не приходить.
2. Можливий дубль у тестовому середовищі: обидві операції залишаються;
   повторний tap не дублює дію, відповідь видно в картці та Mini App.
3. Два договори з однаковою назвою: кнопки відкривають різні ID й суми.
4. До дати та в день платежу чат мовчить. Наступного дня приходить
   зведення лише про непідтверджені записи. Після підтвердження графік
   оновлюється через чинну оплату; сума банківського списання не дублюється.
5. Відкрити платіж чи операцію з Telegram, змінити її в Mini App і
   повернутися: дані оновлюються. Відсутній ID не відкриває інший запис.
6. Помилка D1, конфлікт версії або помилка редагування Telegram:
   немає неправдивого «виконано», повтори безпечні, історія збережена.

Не створювати реальні подвійні списання для перевірки. Автоматичні тести
використовують локальні SQLite/Telegram-заглушки, без даних власника.

## Межі цього блоку

Ще не впроваджуються: чек-ін +90 хв/одноразове продовження, реєстр ключів,
Google-аудит, нова система персоналізації, важливої пошти чи дозвілля.
Окремий iPhone-застосунок і зміна системи deployment залишаються відкладеними.
Нове автоматичне навчання на поясненнях витрат потребує окремо погодженого
контракту спостережень; звичайний облік не називається навчанням моделі.
