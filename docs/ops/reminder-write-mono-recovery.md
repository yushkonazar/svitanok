# Нагадування й тимчасові збої Monobank — 15.10.2026

Виправлення підготовлено локально поверх main `1e42ff6` (root/Mini App 0.10.0).
Наявність цього документа не підтверджує production deployment.

## Нагадати о 21:00

Відтворений запит: «Нагадати о 21:00 аби Сонік змінила рингтон»,
15 жовтня о 00:15 за Києвом. Парсер часу вже підтримував «нагадати»;
помилка була в Brain tool routing: `нагадай`/`нагадуван` не збігалися
з інфінітивом. Модель отримувала загальний набір без reminders_create,
а не справжню відмову D1 чи зміну доступу до запису.

Маршрутизатор тепер розпізнає спільну основу `нагад` і передає лише
дозволені профілем reminder tools. Права Core, taint, рівні T0/T1,
адреса доставки й підтвердження дій не розширюються. Після опівночі
«о 21:00» тут означає 15.10.2026 21:00 Europe/Kyiv, тобто 18:00 UTC.
Текст про Сонік є змістом нагадування власнику, не дозволом писати іншій людині.

Тести перевіряють різні форми запиту, фактичний набір engine tools,
виклик Core та запис у локальну D1 з правильною датою й owner chat.
Не створювати реальне нагадування з цитати автоматично й не підробляти
owner initData для приймання. Виправлення маршруту потребує deployment Brain.

## Monobank

HTTP 500 із `ibus.DealsDepo timeout` — відповідь upstream-банку.
Звірка раніше вже повторювала ту саму фазу, але відразу надсилала
власнику сире технічне повідомлення. Таймаут читання body міг також
помилково перетворитися на успішну порожню відповідь.

- MonoApiError має лише безпечний endpoint label, статус і retryable.
  Ні errorDescription, ні URL, token чи оригінальний network error не
  копіюються до повідомлення/причини помилки.
- HTTP 408/5xx, мережеві та body-read помилки повторюються наступними
  штатними scheduler ticks; повторні спроби в самому адаптері не додаються.
- Перший тимчасовий збій не створює повідомлення. Після 15 хв без
  успішного проходження фази — одне людське попередження за сеанс.
- 401/403 не маскуються під коротку недоступність: зрозуміле попередження
  про доступ відразу. 429/спільний cooldown не запускають outage-таймер.
- Повідомлення про відновлення — лише після завершення всіх statement
  фаз, і тільки якщо власник отримав delayed outage warning.
- Чотиригодинна стеля сеансу збережена; при незавершенні — підсумкове
  попередження, не нескінченний повтор. Збережені операції не видаляються.

Офіційні ліміти client-info та statement — не частіше одного запиту на
60 секунд: <https://api.monobank.ua/docs/>. Існуючі спільні cooldown gates
для Mini App/нічної звірки й lease MonoReconcileDO збережені.

Зміна стану DO/KV — сумісні додаткові поля з нейтральними значеннями
для legacy state. D1 міграцій, ротації ключів, перестворення webhook
або змін банківських операцій для цього виправлення не потрібно.

банківську операцію для перевірки. Авторизоване нагадування — лише
окремою актуальною командою власника.
