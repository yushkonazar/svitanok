# Доступи й повідомлення системи: виконаний блок

Підготовлено локально 11.10.2026 від `main a583398` у гілці
`fix/finance-assistant-ecosystem`. Production deployment не підтверджений.

## Що готове

- У Mini App → Налаштування додано «Доступи й строки дії». Перегляд і запис
  доступні тільки основному власнику; демо й співвласники не отримують реєстру.
- Місця використання відокремлені. OpenAI має Cloudflare (редактор публічних
  новин), VPS (асистент) і GitHub (автоматизації); однакові імена змінних
  не вимагають однакових значень ключів.
- Зберігаються тільки відомі дати та явно обрана політика нагадування.
  Немає поля для значення ключа. Сервер відхиляє невідомі/секретні поля,
  неповні команди й неправильні дати. Запис захищений версією.
- Старі 365-денні розрахунки «строку життя» вилучені. Невідомі дати не
  спричиняють щомісячної розсилки. Старі факти оновлення лишаються довідкою
  без уточненого місця, а не переносом дат на всі ключі.
- Ротація початково вимкнена. Обрану ротацію не називають завершенням
  роботи ключа. Вказана дата завершення має точність до дня за Києвом:
  сьогоднішню дату не видають за вже доведене припинення роботи.
- Сповіщення мають людську назву, місце й кнопку переходу в цей розділ.
  Claim і повідомлення черги записуються атомарно. Один поріг не створює
  нове повідомлення щодня; зміна дати до доставки гасить застарілу картку.
- Збереження метаданих не змінює реальні секрети. Успіх запису відокремлено
  від успіху оновлення екрана. Після втрати мережевої відповіді не вигадується
  ні успіх, ні доведений провал: спочатку пропонується перечитати реєстр.
- Google-аудит відрізняє читання/запис, покриття ширшим правом, дублювання
  й доступ понад поточні функції. `contacts.readonly` разом із `contacts`
  не створює security-алерт. Ширший календарний доступ лишається предметом
  перегляду, а не вимогою негайно відкликати робочий токен.
- Стан Google показує джерело й дату перевірки. Перегляд використовує лише
  кеш, не викликає OAuth або приватні API. Нові кеші прив’язані до grant
  identity; старі не називаються перевіркою поточного grant. Зміна grant
  відкидає його попередній bound-кеш при наступному звичайному зверненні.
- Повідомлення про помилки не містять сирих JSON, HTTP-кодів, scope URI,
  команди перевидачі токена або застарілої «пропозиції співбесід».
  Технічні назви доступні лише у розгорнутих деталях налаштувань.
- Помилки бюджету проєкту OpenAI, вичерпаного кредиту та тимчасової частоти
  запитів розрізнені. Бюджетні помилки не радять лікувати простим повтором.
  Gemini rate-limit не прирівнюється до відсутності коштів.

Звірка бюджетних помилок зроблена з навичкою OpenAI Docs за
[офіційним контрактом помилок](https://developers.openai.com/api/docs/guides/error-codes).
Google — за [Calendar scopes](https://developers.google.com/workspace/calendar/api/auth)
та [OAuth scopes](https://developers.google.com/identity/protocols/oauth2/scopes).

## Межі

Реєстр не є перевіркою валідності кожного ключа. Для Cloudflare показується
наявність у конфігурації, для інших місць — невідомий стан. Ні один із цих
станів не доводить поточний баланс, expiry або готовність зовнішнього API.
Actual Google grants production у цій роботі не читалися й не змінювалися;
проаналізовано активні виклики коду й поведінку нового аудиту на fixtures.

Не видалено legacy Claude path, не змінено схему deployment, секрети,
OAuth-консент, банківські дані або Telegram-дані власника. Нової автоматичної
персоналізації, збору пошти/каналів або розсилки дозвілля не ввімкнено.
Нових модельних запитів для цього блоку немає.

## Реліз і перевірки

Потрібна expand-міграція `0037_credential_metadata.sql` до deployment.
Без неї перегляд інвентаря працює, редагування недоступне й старі вигадані
строки не стають активними. `credential_metadata` та `ops_notices` включені
в backup/export/restore і повне забуття. Перед цим блоком у гілці є також
фінансові зміни та чек-іни з міграцією `0036_checkin_extensions.sql`.

Пройшли 5362 серверних тести, 297 Mini App тестів, typecheck, lint обох
частин і production build Mini App. Ключові нові тести: metadata allowlist,
primary-owner access, незалежні місця, конфлікти версій, atomic rollback,
відомі/невідомі дати, day precision, повторні пороги, старі queued dates,
cached Google evidence, різниця read/write scopes, UI pending/error й
підтвердження запису окремо від читання відповіді.

## Живий чек-ін після публікації

1. Відкрити налаштування → «Доступи й строки дії». Побачити окремі записи
   OpenAI для трьох місць. Невідомий строк не позначений як аварія.
2. Дати можна не заповнювати, якщо вони невідомі. Не використовувати дату
   деплою замість створення/оновлення ключа. Не надсилати значення ключів.
3. Для відомого доступу вказати справжню дату й зберегти. Має з’явитися
   «Дати збережено. Сам ключ не змінено». Інші місця не змінюються.
4. Нагадування ротації лишити вимкненим або обрати свідомо. Переконатися,
   що після повторного відкриття збережено саме цей вибір, не автоматичний рік.
5. Google може показувати «ще не перевірено», якщо кеш застарілий. Це не
   означає поломку. Звичайне читання календаря/пошти оновлює кеш своїм
   штатним шляхом; перегляд цього екрана не просить нових дозволів.
6. Не робити реальної ротації заради тесту. За відомого повідомлення про
   строк його кнопка має відкривати розділ доступів, без зміни самого ключа.

Повний інвентар і безпечні дії: [runbook доступів](secrets.md).
