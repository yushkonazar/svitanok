# Доступи: інвентар, строки дії та ротація

Реєстр описує місця використання, а не значення ключів. Код інвентаря:
[`SECRETS`](../../web/core/ops/secrets.mjs). Кожне місце має окремий запис
у `credential_metadata`. Наявність змінної у Cloudflare не доводить
чинність ключа; конфігурація VPS/GitHub тут не перевіряється.

## Що змінилося

- 365 днів у старому інвентарі були рекомендацією ротації, **не строком
  життя ключа**. Від останнього оновлення більше не обчислюється вигадане
  «закінчення».
- Невідомі дати не викликають автоматичних повідомлень. Їх можна
  заповнити пізніше в Mini App → Налаштування → Доступи й строки дії.
- Строк у провайдера вводиться лише якщо він відомий. Обране нагадування
  про ротацію — окреме поле й початково вимкнене. Таблиця нижче не вмикає його.
- Старі `facts.setting.secret_rotated_<НАЗВА>` лишаються довідкою без
  уточненого місця. Не переносимо їх автоматично на всі копії ключа.
- `OPENAI_API_KEY` використовується в Cloudflare для публічних новин,
  на VPS для асистента та в Actions для автоматизацій. Це можуть бути
  різні ключі; однакова назва не означає однакове значення.
- Legacy Claude/LLM-host лишаються в інвентарі, але приховані у звичайному
  перегляді. Цей блок не видаляє fallback або токени: cleanup потребує
  окремого погодження, rollback-tag і restore drill.

## Які дані вказати

- Назву й місце використання обирають зі списку, а не вводять довільно.
- Останнє оновлення — тільки відома дата. GitHub `updated_at` означає
  оновлення запису, не строк дії токена у провайдера.
- Строк дії — дата, показана провайдером. Якщо її немає, поле порожнє.
  Реєстр має точність до дня за Києвом, не підтверджує чинність до певної хвилини.
- Інтервал ротації задається окремо, за бажанням. Потрібна дата останнього
  оновлення. Кнопка зберігає **тільки метадані**, не оновлює реальний секрет.

Значення ключів, refresh-токени, приватні ключі, OAuth-коди й файли `.env`
не надсилати в чат або форму. API приймає лише allowlisted поля метаданих.
Інвентар доступний лише основному власнику; демо та співвласники не читають його.

## Сповіщення

`secret-expiry` перевіряє відомі дати о 10:00 за Києвом. Для фактичного
строку — пороги 30 днів, 7 днів та вже минула дата; для обраної ротації —
окремий текст, без твердження, що ключ перестав працювати. Невідоме не
перетворюється на аварію. Один запис на місце/дату/поріг, а не щоденний дубль.
Черга повторює доставку; зміна дати до відправлення гасить старе повідомлення.
Кнопка відкриває цей розділ Mini App.

## Google: реальні можливості, не дослівне порівняння рядків

`web/core/google-scopes.mjs` і `scripts/google-auth.mjs` використовують
той самий контракт. Поточні Worker-виклики: події календаря, читання Gmail,
пошук/створення контактів, створення власних файлів та явний пошук/читання
Drive, створення/видалення Tasks. Доступ для надсилання листів не запитується.

- Ширше право може покривати потрібне: це не «бракує дозволу», але може
  вимагати перегляду зайвого доступу.
- `contacts.readonly` разом із `contacts` дублює вже надане читання.
  Дублювання не спричиняє security-алерт.
- `calendar.readonly` ширше за читання самих подій і не просто дублює
  `calendar.events`: для поточних шляхів варто окремо переглянути його
  необхідність. Автоматичного відкликання чи перепідключення немає.
- Перегляд реєстру не викликає OAuth або приватні Google API. Джерело
  перевірки — кеш успішного обміну; показується його дата й рівень доказу.
  Старий/невідомий кеш не називається актуально перевіреним.
- Нова відповідь OAuth прив’язана до ідентичності client/refresh grant
  серверним digest. Digest і токени не потрапляють у Mini App.
- Повторне попередження про той самий надлишковий/відсутній доступ —
  не раніше ніж через 30 днів. Зміна проблеми може створити нове повідомлення.

Офіційні контракти: [Calendar API scopes](https://developers.google.com/workspace/calendar/api/auth),
[OAuth scopes, зокрема People API](https://developers.google.com/identity/protocols/oauth2/scopes).

## Безпечна реальна ротація — окремо від реєстру

1. Перевірити провайдера, місце використання й термін. Не змінювати
   непов’язані копії лише через однакову назву.
2. Якщо провайдер дозволяє, підготувати новий ключ до відкликання старого.
   BotFather може відкликати старий відразу — врахувати коротку перерву.
3. Оновити тільки потрібне сховище секретів, перевірити відповідну можливість.
4. Відкликати старий після підтвердження роботи нового, якщо це дозволено.
5. Записати відомі метадані конкретного місця в реєстр.

Google OAuth виконується вручну за `scripts/google-auth.mjs`; погодити
набір прав перед запуском. Google-токен не потрібен у GitHub Actions.
`BACKUP_ENC_KEY` не змінювати без перешифрування бекапів і перевірки відновлення.
HMAC-перехід передбачає `INTERNAL_HMAC_KEY_NEXT`; не прибирати старий
до перевірки взаємодії Worker і VPS. Нічого з цих операцій реєстр не робить сам.

## Помилки бюджету — не помилки строку ключа

Досягнутий бюджет проєкту OpenAI, вичерпаний кредит та тимчасова частота
запитів — різні випадки. Повтор запиту не відновлює доступ після помилки
бюджету або кредиту; це враховано в людському повідомленні та існуючому
захисті від повторних платних викликів.
Джерело: [OpenAI API error codes](https://developers.openai.com/api/docs/guides/error-codes).

## Реліз

Потрібна expand-міграція `0037_credential_metadata.sql` до ввімкнення
редагування. Без неї реєстр лише читається, попередження зі старих
365-денних припущень не відновлюються. Таблиці включені в backup/export/restore
та повне забуття. Цей документ не підтверджує production deployment.
