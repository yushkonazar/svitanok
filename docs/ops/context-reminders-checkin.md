# Нагадування «після роботи»: реалізація і приймання

05.10.2026. Реалізовано в локальній гілці `feat/work-context-reminders`,
не задеплоєно. Гілка включає попереднє виправлення життєвого циклу даних.

## Що працює

- «Нагадай [мені] [сьогодні/завтра] після роботи …» зберігає справу без `due_at`.
- Текст і підтверджений голос проходять той самий детермінований маршрут,
  без модельного виклику для створення/завершення/кнопок.
- «Закінчив працювати», «Завершив роботу», «Роботу завершено» або однойменна
  кнопка фіксують фактичне завершення. Планова година сама нічого не запускає.
- «Їду/йду/повертаюсь додому»: за фактичного старту роботи або робочого блоку
  прийнятого плану — завершення; інакше питання «Роботу завершив?» з кнопками.
- Негативні, майбутні, цитовані фрази й «їду додому на перерву» не запускають
  детерміновану подію. Загальний розмовний маршрут не отримує нового інструмента
  завершення зміни й не може обійти цей guard.
- Уточнення зберігається у D1, переживає інші запити; діє 10 хвилин. Після
  погодження та сама картка перетворюється на нумерований список справ.
- Для кожної справи: «Готово», «Не зараз», «Завтра», «Прибрати».
  «Не зараз» залишає її незавершеною у `/remind` і `/digest`, не вигадує час.
- Нова справа після завершення просить вибір «Зараз» / «Завтра після роботи»;
  старі справи не перевидаються. «Завтра» означає саме наступну календарну дату,
  а не автоматичне визначення наступної робочої зміни чи перенесення через вихідні.
- «Змінити» відкриває явне уточнення: «Нова справа: …». Інші повідомлення
  не поглинаються як відповідь. Вікно — 10 хвилин; одночасно редагується
  остання обрана справа у цьому чаті/темі.
- `/new` не видаляє справи або факт завершення. Чат і тема ізольовані;
  дії доступні лише головному власнику. Старі й повторні кнопки не відроджують
  завершені/скасовані справи.

## Межі першої версії

Зміна відбирається за активованим контекстом поточного дня або останніх
20 годин, із датою не пізнішою за сьогодні. Заздалегідь створена завтрашня
зміна не перехоплює справи поточної нічної зміни. «Почав працювати» активує
її зі збереженими справами. Це зберігає нічну зміну через північ; не є обіцянкою
підтримки довільно довгих змін. Після завершення «Почав працювати» відкриває
нову зміну, зокрема того самого дня. До 20 активних справ на зміну,
назва до 140 символів: картка вкладається у ліміти Telegram.

Немає повтору «щодня після роботи», довільних дат після ключа «після роботи»,
відкату словом «відміни останнє» (замість ризику відкотити давнішу дію —
пояснення й кнопки конкретної справи),
автоматичного пошуку найближчої зміни за календарем, геофенсингу або автоматичного
перепланування вечора. Для повтору є чесна відповідь про непідтримувану функцію.
Прострочені невиконані справи залишаються у списку, не переносяться мовчки.
Пропущену стару зміну не можна закрити кнопкою іншої поточної зміни.

## Надійність і дані

Ключ вихідного повідомлення дедуплікує створення. D1 batch однією транзакцією
фіксує завершення, склад групи, claims справ і її outbox-повідомлення.
Порожні конкуруючі групи не залишаються. Відновлення під час drain підбирає
справи, створені одночасно із завершенням або після збою між підтвердженням
і постановкою в чергу. Воно працює лише за **вже записаною фактичною подією**.

Відомий Telegram 429 має retry. Невідомий результат нового send після
мережевого збою, HTTP 5xx або завислого sending-claim отримує статус `uncertain`:
автоматичного повтору немає. `/remind` показує збережені справи та пояснення,
тож власник може сам їх переглянути. Це не гарантія exactly-once доставки
зовнішнім API. Edit можна повторити без нового повідомлення. Видалена картка
не спричиняє сліпого fallback-send: актуальні справи доступні через `/remind`.

Нове повідомлення-відповідь на дію власника не пригнічується focus/тихими
годинами. Статус `notified` — claim картки, а не доказ отримання й не `done`;
фактичний стан доставки міститься в outbox. Історія виконаних/скасованих справ
живе 12 місяців; активні справи не видаляються; невизначена доставка — 90 діб.
Усі три нові таблиці включені до backup/export/forget-all.

## Порядок релізу

Не пушити гілку навмання: підключений Cloudflare build може задеплоїти її.
Спочатку перевірити target/trigger/CI і застосувати expand-міграцію `0034`
до D1, потім оновлювати Worker. Поточну систему деплою цей блок не змінює.
Узгоджений оператор виконує з каталогу `web`:

```powershell
npx wrangler d1 migrations list svitanok --remote
npx wrangler d1 migrations apply svitanok --remote
```

Перед apply перевірити весь список pending: команда застосовує **всі**
міграції, а не тільки `0034`. Ці команди тут не виконувалися.
Rollback — попередня Worker-версія без видалення нових таблиць; export
до будь-яких руйнівних дій. Не запускати `/forget усе` для живого тесту.

## Повідомлення для живого чек-іну після релізу

1. «Нагадай після роботи: тест — лимон, заїхати в Сільпо».
2. «Нагадай після роботи: тест — лимон, забрати посилку».
3. «Їду додому на перерву» — список не повинен спрацювати.
4. «Їду додому» — за невідомого робочого контексту має уточнити завершення.
5. Перед відповіддю на питання: `/digest`; потім натиснути «Так, завершив».
   Питання перетвориться на одну картку обох справ.
6. Для першої справи «Не зараз», для другої «Готово»; `/remind` і `/digest`
   повинні залишити лише першу незавершеною.
7. Знову «Їду додому» — старий список не надсилається повторно.
8. «Нагадай після роботи: ще один тест — лимон» — вибір поточної/завтрашньої
   справи, не мовчазне додавання до старої групи.
9. Обрати «Зараз» — лише нова справа. Для неї «Завтра» — старі кнопки
   не повинні позначати перенесену справу виконаною.
10. Перевірити голосом крок 1; перевірити «Змінити» → інший запит →
    «Нова справа: тест — лимон, купити воду»; `/new` не стирає залишок.

Після тесту прибрати лише ці тестові справи їхніми кнопками.
Локальні тести: `tests/context-reminders.test.ts`, schema/lifecycle,
ретенція, outbox та повний regression suite; зовнішні запити — лише synthetic stubs.

Фінальна локальна перевірка: **5 147 тестів у 245 файлах**, із них 44 нові
перевірки контекстних нагадувань. `typecheck`, `lint`, `format:check`, контракт
інструментів і `git diff --check` пройшли. Це не заміна живого чек-іну після релізу.
