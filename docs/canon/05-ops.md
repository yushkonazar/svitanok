# 05 · Експлуатація: середовища, секрети, деплой, бекапи, алерти, інциденти

## 1. Середовище

Одне - prod (ADR-009). Гілки: `feature/*` → PR у `develop` → PR у `main` → Cloudflare Git-інтеграція деплоїть Worker; `deploy-host.yml` деплоїть мозок на VPS (`svitanok-brain.service`, `127.0.0.1:8788`, Tunnel `brain.<домен>`). Новий функціонал живе за прапорцем `ASSISTANT_V2` (`off` → `shadow` → `on`, 01 §5). Приймання - власником у проді за чеклістами 03-plan. Старий `host/` (`svitanok-llm-host.service`, Caddy, :443) працює до `on`, потім вимикається і видаляється.

Dev-цикл без staging: `wrangler dev --remote` для локального прогону Worker з прод-bindings лише для читання (D1 - на локальній копії `--local` з міграціями), `npm test` з моками; мозок локально - `npm run dev` у `brain/` проти `wrangler dev` через `INTERNAL_API_URL=http://127.0.0.1:8787`.

## 4. Деплой

**Ядро:** push у `develop`/`main` → Cloudflare Git-інтеграція (як зараз; `wrangler.jsonc` з env). Міграції D1 - крок CI перед деплоєм (`wrangler d1 migrations apply --env …`); міграція, що не пройшла, блокує деплой. Після деплою - smoke з CI: `GET /status` + `brain-health` очікуваної версії.

**Мозок:** `deploy-host.yml` (paths `brain/**`): `appleboy/ssh-action` → `cd /opt/svitanok-brain && git fetch && git checkout <sha> && npm ci --omit=dev && npm run build && sudo systemctl restart svitanok-brain` → `curl 127.0.0.1:8788/health` → версія = sha. sudoers: `brain ALL=(root) NOPASSWD: /bin/systemctl restart svitanok-brain`. Відкат: `git checkout <попередній sha>` тією ж дією (`workflow_dispatch` з параметром sha).

**Інструкції:** `sync-instructions.yml` (paths `docs/assistant/**`): перевірка front-matter і `max_chars` → хеш → `PUT` у D1 (з `main`) → тест парності в `ci.yml`.

**VPS одноразово (етап 1):** користувач `brain` без sudo (крім restart), `/opt/svitanok-brain` (git clone, deploy-ключ read-only), Node LTS, `cloudflared` як сервіс з одним hostname, systemd-юніти з `ProtectSystem=strict`, `ProtectHome=true`, `NoNewPrivileges=true`, `PrivateTmp=true`, `ReadWritePaths=/opt/svitanok-brain/data` (сесії SDK), `EnvironmentFile=/opt/svitanok-brain/.env`; ufw: лише SSH; Caddy і 443 вимкнути після переходу на Tunnel; `unattended-upgrades` увімкнено; journald 30 днів.

## 6. Бекапи і відновлення

- Нд 03:00 (`backup`): `wrangler d1 export` еквівалент через REST (або `SELECT` по таблицях у JSON) + KV-знімок (усі ключі) → AES-256-GCM → Drive `Світанок/backups/svitanok-YYYY-MM-DD.enc` через `drive.file`. Файли зберігаються 90 діб; `retention-cleanup` видаляє лише цей точний app-owned шаблон безповоротним Drive `DELETE`. Без ротації (рішення R16).
- Перевірка: хеш файлу в `facts.setting.last_backup` + повідомлення в TOPIC_SYSTEM лише при помилці.
- Відновлення: `scripts/restore.mjs --file <enc> --dry-run` (показує, що зміниться) → без `--dry-run` → розшифрувати → `wrangler d1 execute` (таблиці truncate+insert у транзакції) → KV put → smoke. Раз на квартал - тестове відновлення у локальну D1 (`wrangler d1 --local`) (задача `backup` кожної 13-ї неділі шле нагадування).
- D1 Time Travel (30 днів на Paid) - для відкату помилкової міграції: `wrangler d1 time-travel restore --timestamp`.
- Чек-ін у KV `stats` входить у знімок KV - і тільки так (новий код його не змінює).

## 7. Інциденти (playbook)

### 7.1 Мозок не відповідає

1. `TOPIC_SYSTEM` показує останню помилку `brain-health`. 2. На VPS: `systemctl status svitanok-brain`, `journalctl -u svitanok-brain -n 100`. 3. Типові причини: закінчився Claude-токен (401) → runbook §3; `cloudflared` впав → `systemctl restart cloudflared`; OOM → `free -m`, перезапуск. 4. Поки лежить - ядро відповідає «недоступний», черга до 3 спроб; нагадування/планувальник/Mono працюють (без LLM).

### 7.2 Зміна політики підписки (403/`usage-limit` постійно)

1. Алерт з текстом помилки. 2. Перевірити support.claude.com (стаття 15036540). 3. Рішення власника: чекати / Max вище / план Б (API-ключ у `brain/.env`, кап у консолі) - ADR-002.

### 7.3 Google-токен мертвий

1. Кнопка «Переавторизуватись» → `scripts/google-auth.mjs` локально → новий refresh-токен → `wrangler secret put` → «що в календарі» працює.

### 7.4 Telegram-токен скомпрометований

1. BotFather `/revoke` → новий токен → `wrangler secret put` → `tg-setup` → перевірка. 2. Перевірити `runs` за останні години на чужі chat_id (allowlist мав відкинути).

### 7.5 Підозра на витік даних з VPS

1. Відкликати Access service token і Claude-токен; 2. `journalctl` + `last`; 3. Ротація всіх секретів мозку (3 шт.); 4. Перевірка `authorized_keys`.

### 7.6 D1 пошкоджено міграцією

1. `wrangler d1 time-travel restore` на момент перед міграцією; 2. Виправити міграцію; 3. Повторити на локальній D1 (`--local`) → prod.

### 7.7 Mono шле невідомі транзакції

1. Перевірити `account` з `client-info`; 2. Якщо чужий акаунт - відкликати токен у Mono, новий токен, ротація `MONO_WEBHOOK_SECRET`.

## 8. Витрати - облік

`quota_counters` щомісяця: Places Text/Details, Routes, Gemini $ (за відповідями API), Deepgram хв, Actions хв, Workflows кроки. Блок «СИСТЕМА» звіту показує $ проти стелі $15. Будь-яка нова платна дія - лише через `proposals` з ціною (T1/T2).
