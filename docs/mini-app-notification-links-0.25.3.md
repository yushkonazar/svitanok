# 0.25.3 · Кнопка повідомлення відкриває потрібну сторінку

Стан: підготовлено до перевірки й публікації. Версія пакета сама по собі не підтверджує production deployment.

## Причина

Кнопки чек-інів, оглядів, плану й фінансів уже передавали `startapp` із контекстом. Telegram може додати службові параметри у fragment, який також читає `HashRouter`. Два окремі ефекти `App` одночасно відкривали цільову сторінку й скидали невідомий службовий маршрут на головну. У регресії з реальним `HashRouter` і `StrictMode` чек-ін та огляд обидва опинялися на `/`.

Клієнт читав лише `initDataUnsafe.start_param`, пропускаючи документований URL-параметр `tgWebAppStartParam`. Команда `/settings` окремо створювала кнопку головної без адреси налаштувань.

## Поведінка

Адреса повідомлення визначається перед монтуванням оболонки та її перевіркою невідомих маршрутів. Дата, слот, тиждень та ID запису зберігаються. Новий службовий fragment обробляється також у відкритому WebView. Подальша ручна навігація не повертає користувача до початкового повідомлення.

Клієнт читає свіжий параметр URL перед SDK, потім `initDataUnsafe.start_param` і відповідне поле сирого `initData`. Порожній явний параметр не відновлює стару ціль SDK; довжина обмежена, невідомі цілі переходять на головну. Це лише вибір екрана: серверна авторизація, строки чек-інів і підтвердження дій залишаються чинними. Перехід не переносить слот і не записує відповідь.

| Кнопка              | Сторінка та контекст                                |
| ------------------- | --------------------------------------------------- |
| Чек-ін              | `/checkin`, дата та ранковий/денний/вечірній слот   |
| Тижневий огляд      | `/weekly-report`, конкретний тиждень                |
| План                | `/plan`, дата або задача                            |
| Операція чи платіж  | `/finance`, ID запису                               |
| Дозвілля            | `/leisure`, розділ або матеріал                     |
| Доступи             | `/settings?panel=access`                            |
| `/settings`         | `/settings`, включно з приватним `web_app` fallback |
| Інші відомі розділи | Відповідна вкладка, збережене, закладки або пам’ять |

На «Сьогодні» є помітний вхід «Тижневі огляди», доступний також до завантаження брифінгу. Посилання у «Моєму стані» збережено. Раніше надіслані чек-іни й огляди з параметром підтримуються. Старі загальні кнопки без адреси не містять контексту для відновлення; `/settings` отримує адресу в нових відповідях.

## Перевірки та публікація

Регресії охоплюють реальні генератори кнопок і `HashRouter`, службові fragment-и з `#`/`#?`, GET-only запуск, відновлений попередній екран, повторне відкриття WebView, ручну навігацію, прямий `web_app` маршрут і доступ до оглядів із головної. Перевірки читання параметрів не встановлюють авторизацію через URL. Існуюча інтеграція чек-іну перевіряє, що прострочене адресоване вікно не перемикається на інший слот.

Публікація використовує чинний Worker/Mini App pipeline після перевірки Cloudflare deployment settings. Міграцій і змін Brain немає. Особисті записи не переписуються. Локальні тести відтворюють умови запуску; перевірка на реальному iPhone у Telegram виконується після публікації.

Контракт: [Telegram Mini Apps](https://core.telegram.org/bots/webapps#direct-link-mini-apps), [посилання головної Mini App](https://core.telegram.org/api/links#main-mini-app-links).
