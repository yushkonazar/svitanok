# Робочі періоди таксі · 0.12.0

День і час перезмінки задаються за Києвом, з урахуванням літнього/зимового часу. Початкові періоди понеділок 13:00 залишаються історичними. Новий розклад не перегруповує попередні розраховані тижні.

## Зміна авто

Фінанси → Таксі → «Каса, умови та розрахунки» → «Додатково · зміна авто чи дня перезмінки».

1. Вкажи назву авто/режиму, точну дату й час переходу, новий день і час регулярної перезмінки.
2. Вибери «Гібрид · завжди 50/50» або збереження чинних часток. Гібрид ділить касу, комісію, пальне й чайові в застосунку навпіл; поріг та підвищення частки вимкнені. Поза цими сумами особистий дохід обліковується окремо, як раніше.
3. Для записів, які вже внесено після часу переходу, явно обери попереднє або нове авто. Система не вгадує за часом введення. Внесені раніше записи залишаються в попередньому періоді.
4. Перевір обидва періоди, кількість записів, заробіток і розрахунок із парком. Підтвердь перехід.

Перехід закриває попередній період у вказаний момент і відкриває короткий період до найближчої нової перезмінки. Далі працює звичайний семиденний графік. Зміни в межах одного дня мають різні ключі; періоди впорядковані за фактичним початком.

Заробіток і поріг рахуються окремо для кожного робочого періоду; округлення — один раз для його версії умов. Каса гібриду не підвищує частку попереднього авто. Перехід не створює грошового переказу та не позначає оплату парку. Фактичну суму можна окремо вказати через історію перезмінок, зокрема прив’язати банківський платіж після закриття періоду.

## Доповнення й історія

У формі запису зміни є вибір «Авто й робочий період». Типово період визначається за датою й часом. Для пізнього доповнення попереднього авто обери його незакритий розрахунком період: дата введення збережеться, умови візьмуться з того періоду. При редагуванні явна прив’язка зберігається; вибір «Автоматично» прибирає її.

Уже розраховані з парком періоди та їхні записи захищені від зміни. Перехід, який зачіпає такий період, відхиляється. Конфлікт із уже збереженими майбутніми умовами потребує звірки; нові умови не перекриваються мовчки.

Історія, головний блок, аналітика, фінансові звіти й пояснення асистента використовують спільне ядро розрахунку. Календарні фінансові бюджети й звіти за тиждень залишаються календарними; робочі періоди таксі показуються з власними межами.

## Зберігання й реліз

Expand-міграція `0043_taxi_work_periods.sql`: JSON метаданих розкладу в `finance_taxi_policies.period_json` та необов’язкова явна прив’язка `finance_taxi_entries.period_key`. Старі рядки читаються з попереднім розкладом. Розклад не є глобальним перемикачем, що переписує історію.

Перехід виконується однією пакетною командою зі звичайним захистом версії та повторного ID. Оригінальні часи, суми, касові операції й уже підтверджені оплати не переписуються. Змінюється лише версія умов/прив’язка тих записів, які підтверджено на екрані перевірки. Моделі, банківські запити та нові секрети для цього не потрібні.

Перевірки охоплюють п’ятничний перехід, середу о 12:00, перехід часу, пізній старий запис, незалежність порога, кілька змін авто в один день, повтор команди, закриті розрахунки, історичні звіти та два кроки підтвердження в мобільному інтерфейсі.
